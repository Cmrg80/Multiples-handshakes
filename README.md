This project analyzes the performance impact of repeated TLS handshakes using OpenSSL.
The original objective was to study the accumulated latency generated by multiple TLS handshakes in client-server and microservice-like scenarios.

During experimentation, an unexpected behavior was observed:

Under localhost conditions, TLS 1.2 produced slightly faster handshake benchmarks than TLS 1.3.

This repository focuses on reproducing, measuring, and analyzing that behavior.

Objectives: 

Benchmark repeated TLS handshakes
Compare TLS 1.2 and TLS 1.3 performance
Analyze handshake computational overhead
Separate network latency from cryptographic cost
Provide reproducible benchmarking pipelines

Background

TLS handshake latency is composed of two major components:

| Component          | Description                   |
| ------------------ | ----------------------------- |
| Network latency    | RTT between client and server |
| Computational cost | Cryptographic processing      |

TLS 1.3 was designed to reduce the number of RTTs:

| Protocol | TLS RTT |
| -------- | ------- |
| TLS 1.2  | 2 RTT   |
| TLS 1.3  | 1 RTT   |

However, in localhost benchmarks:
RTT ≈ 0 ms

The network advantage disappears, exposing mostly:

CPU cost
OpenSSL implementation overhead
cryptographic operations

This project isolates those factors.

Why TLS 1.3 Should Be Faster

TLS 1.3 reduces startup latency by:

reducing round trips
simplifying negotiation
enforcing modern cryptography
integrating ephemeral key exchange earlier

Why TLS 1.2 Can Appear Faster on localhost

Because localhost removes network latency, the benchmark primarily measures:

cryptographic processing
OpenSSL implementation details
CPU optimizations
AES-NI / AVX acceleration
scheduler overhead

This does not contradict TLS 1.3 design goals.

Running the Benchmark
1. Start TLS Server
  openssl s_server -accept 4433 -cert cert.pem -key key.pem
2. Run TLS 1.3 Benchmark
  openssl s_time -connect localhost:4433 -new -time 30 -tls1_3
3. Run TLS 1.2 Benchmark
  openssl s_time -connect localhost:4433 -new -time 30 -tls1_2
